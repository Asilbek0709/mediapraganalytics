# MediaPrag-Analytics

**Mediamatnlarning lisoniy-pragmatik tahliliy platformasi** — цифровая аналитическая платформа для лингвопрагматического анализа и оценки медиатекстов.

Платформа не использует ИИ. Исследователь размечает материал (кодирование), система хранит разметку, рассчитывает индекс **LPSI** по методике III главы, сравнивает издания и формирует отчёт.

```
медиатекст → ввод → кодирование → оценка по критериям → автоматический расчёт → аналитика → отчёт
```

## Технологии

Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Framer Motion, ExcelJS, PDFKit (шрифт DejaVu Sans). База данных — **PostgreSQL**:

- **онлайн** — Supabase (переменная `DATABASE_URL`), сервер на Vercel;
- **на компьютере** — PGlite, полноценный PostgreSQL внутри Node.js, без установки и без интернета (папка `data/pglite`).

SQL в обоих случаях один и тот же. Нужен **Node.js 24**.

## Запуск

| Файл | Что делает |
|---|---|
| `start_web.bat` | Рабочая платформа → http://localhost:3100. База — из `DATABASE_URL` в `.env.local` (Supabase) или, если его нет, `data/pglite` на этом компьютере |
| `start_web_demo.bat` | Демо-данные → http://localhost:3101, всегда отдельная база `data/demo-pglite` (при первом запуске заполняется из `data/demo.db`) |

При первом запуске сам ставит библиотеки (`npm install`) и собирает приложение (`npm run build`). После изменения кода пересоберите приложение: `npm run build`.

Порты 3100/3101 выбраны, чтобы не пересекаться с другими Next.js-проектами на порту 3000. Для разработки: `npm run dev -- -p 3100`. Переменные окружения описаны в `.env.example`. Явно заданная `MEDIAPRAG_DB` (папка PGlite) всегда важнее `DATABASE_URL`, поэтому демо-режим никогда не пишет в рабочую базу.

**Доступ только с этого компьютера.** Сервер слушает адрес `127.0.0.1` (`next start -H 127.0.0.1`): с других устройств сети платформа недоступна. Вход по паролю действует и здесь (см. «Вход и роли»).

Демо-данные вымышлены и помечены `[DEMO]`: они нужны только для просмотра графиков, в диссертации их использовать нельзя.

## Вход и роли

При первом открытии платформа предлагает создать **первого администратора**. После этого:

- **Регистрация.** На странице входа любой может создать учётную запись (вкладка «Регистрация»). Она получает роль **наблюдателя** (только просмотр). Чтобы сделать человека экспертом, администратор на странице «Foydalanuvchilar» меняет ему роль на «Эксперт», и учётная запись привязывается к записи эксперта. Там же регистрацию можно выключить, а самостоятельно зарегистрировавшиеся отмечены. От ботов защищают скрытое поле-ловушка и лимит: не больше 30 новых учётных записей в час.
- Учётные записи с любой ролью администратор может создать и сам — с временным паролем.

| | Администратор | Эксперт | Наблюдатель |
|---|---|---|---|
| Добавление и правка материалов, импорт, основная разметка, правка методики | ✓ | — | — |
| Своя независимая разметка, опрос по весам («Мои задания») | — | ✓ | — |
| Панель, аналитика, корпус примеров, отчёт | ✓ | только просмотр | только просмотр |
| Mediabaza, методика, раздел «Ekspertlar» | ✓ | только просмотр | — |
| Чужие разметки, основная разметка в карточке анализа, сравнение экспертов по материалу | ✓ | не видит | не видит |
| Отчёты Excel и PDF по изданиям | ✓ | ✓ | ✓ |
| Пользователи, резервные копии | ✓ | — | — |

- **Независимость экспертов.** Эксперт видит все разделы, кроме «Пользователей», но менять может только свою разметку и свои веса. Чужие разметки и основную разметку в карточке анализа он не видит: иначе его разметка перестаёт быть независимой и α Криппендорфа теряет смысл. Учтите: панель, аналитика, Mediabaza и корпус примеров построены на основной разметке, поэтому общие результаты исследователя эксперту видны. В разделе «Ekspertlar» скрыты веса других экспертов и сравнение по отдельным материалам. Учётная запись эксперта привязана к его записи в разделе «Ekspertlar». Карточка анализа у эксперта всегда открывает только его слой, какой бы адрес ни был набран.
- **Пароли.** Новая запись получает временный пароль. Администратор передаёт его человеку сам, и при первом входе тот обязан задать свой. Администратор может сбросить пароль (новый временный, все сеансы завершаются) и отключить запись. Последнего активного администратора отключить или понизить нельзя.
- **Безопасность.**
  - Пароли хранятся только как хеш scrypt со случайной солью.
  - Сеанс — случайный токен в cookie HttpOnly, SameSite=Lax, Secure на HTTPS; в базе хранится только его SHA-256, срок 14 дней.
  - После 5 неверных попыток за 15 минут вход по этому email временно блокируется.
  - Доступ проверяется дважды: в proxy по общей таблице ролей (`lib/ruxsat.ts`; путь, которого нет в таблице, открыт только администратору) и внутри каждой страницы и API.
- **Первый администратор онлайн.** В онлайн-версии создание первого администратора требует ключ `MEDIAPRAG_SOZLASH_KALITI` из настроек Vercel. Пока администратора нет, открыть сайт мог бы кто угодно — ключ это закрывает.

## Онлайн: Supabase + Vercel

1. **Supabase.** Создайте проект на supabase.com (регион — Frankfurt, eu-central-1). Скопируйте строку подключения: **Connect → Transaction pooler** (порт 6543) и подставьте в неё пароль базы. Таблицы создавать не нужно: платформа создаёт их сама при первом обращении.
2. **Vercel → Settings → Environment Variables:**
   - `DATABASE_URL` — строка подключения из шага 1;
   - `MEDIAPRAG_SOZLASH_KALITI` — любая длинная случайная строка (от 12 символов), нужна один раз для создания администратора;
   - `CRON_SECRET` — ещё одна случайная строка: с ней Vercel каждую ночь вызывает создание резервной копии (`vercel.json`, 03:00 по Ташкенту). Без неё ежедневная копия по расписанию не работает, остаётся только копия при работе с платформой.

   Затем сделайте **Redeploy**.
3. Откройте сайт, создайте первого администратора (понадобится ключ из шага 2) и заведите учётные записи экспертов и наблюдателей.
4. **Перенос старых данных (по желанию).** Старую базу SQLite (`.db`) можно загрузить через «Отчёт → Резервная копия → Добавить из файла» и восстановить. Другой способ — из командной строки, указав `DATABASE_URL`:

   ```
   npm run import:sqlite -- data/старая-база.db
   ```

   Данные в базе заменяются, учётные записи не трогаются.

Чтобы локальная платформа (`start_web.bat`) работала с той же облачной базой, положите `DATABASE_URL` в файл `.env.local` рядом с проектом. Этот файл в git не попадает.

## Язык и оформление

**Телефоны и планшеты.** На сенсорных экранах и в окнах уже 1024 px платформа включает облегчённый режим: фон не двигается, нет бесконечных анимаций и «стеклянного» размытия, у графиков нет теней. Эти эффекты постоянно нагружают видеокарту телефона. Внешний вид и цвета те же. PDF.js и распознавание текста загружаются только при добавлении материала из файла.

Переключатели в шапке:

- **Язык интерфейса** — UZ (узбекский, латиница; по умолчанию), RU, EN. Переводится весь интерфейс, сообщения сервера и ошибки импорта, а также файлы: Excel-отчёт, PDF-карточка и шаблон импорта формируются на выбранном языке. Научные термины методики (критерии, категории, типы заголовков, уровни шкалы) переводятся по коду; если исследователь переименовал термин на странице «Metodika», показывается его название. Данные (заголовки, тексты, издания, комментарии) не переводятся.
- **Тема** — светлая, тёмная или «как в системе». Смена анимируется круговым раскрытием от кнопки (если в системе не отключены анимации).

Выбор хранится в cookie `mp_til` и `mp_mavzu`, поэтому страница сразу открывается в нужном языке и теме, без мигания. Словари — `lib/i18n/matnlar/*.ts`; TypeScript проверяет, что у всех трёх языков одинаковый набор ключей.

## Формула LPSI (значения по умолчанию)

| Критерий | Вес | Расчёт |
|---|---|---|
| K1. Pragmatik muvofiqlik | 25% | среднее трёх связей × 100 (mos = 1, qisman = 0,5, mos emas = 0) |
| K2. Semantik aniqlik | 25% | 100 − 10 × (семантические неточности) |
| K3. Lisoniy-uslubiy me’yor | 20% | 100 − 10 × (стилистические ошибки) |
| K4. Kompozitsion yaxlitlik | 15% | mantiqiy 100 · ketma-ket 80 · aralash 60 · buzilgan 30 |
| K5. Auditoriya uchun aniqlik | 15% | (оценка − 1) / 4 × 100 − 10 × (контекстуальные несоответствия) |

**LPSI = Σ (вес × K) / 100.** Шкала: 0–40 past · до 60 qoniqarli · до 80 yaxshi · до 100 yuqori. Все числа меняются на странице «Metodika».

Сводные показатели считаются только по полностью проанализированным материалам. «Доля проблемы, %» — доля материалов, где категория встретилась хотя бы один раз.

## Статистическая значимость различий

Карточка «Statistik ahamiyat» на странице «Analitika» и лист Excel «Значимость различий» отвечают на вопрос, не случайна ли разница между группами (α = 0,05). Тесты непараметрические: баллы ограничены 0–100 и распределены не нормально, группы небольшие.

| Сравнение | Тест | Размер эффекта |
|---|---|---|
| Печатные и цифровые СМИ: K1–K5, LPSI | Манн–Уитни U (точное распределение для малых групп без связок, иначе нормальное приближение с поправкой на связки) | рангово-бисериальная r: 0,1 / 0,3 / 0,5 |
| Доля материалов с проблемой: печатные и цифровые | точный критерий Фишера 2×2, поправка Холма по всем категориям | — |
| Издания, жанры, годы: K1–K5, LPSI | Краскел–Уоллис H; при значимом H — пост-хок Данна с поправкой Холма | ε²: 0,01 / 0,08 / 0,26 |
| Период A и период B: K1–K5, LPSI | Манн–Уитни U | r: 0,1 / 0,3 / 0,5 (r > 0 — выше в периоде B) |
| Период A и период B: доля материалов с проблемой | точный критерий Фишера 2×2, поправка Холма | — |

В сравнение изданий, жанров и лет входят группы от 3 материалов (меньшие перечисляются как исключённые); при группах меньше 5 выводится предупреждение. Материалы без жанра в сравнение жанров не входят, без даты — в сравнение лет и периодов. Тесты учитывают фильтры страницы; Excel считает по всем полностью размеченным материалам. Расчёты повторяют `wilcox.test`, `kruskal.test` и `fisher.test` из R.

## Сравнение периодов и рейтинг

**Сравнение периодов** (карточка «Davrlarni taqqoslash» на странице «Analitika») — два произвольных периода A и B с датами начала и конца:
- готовые пары: соседние годы («2024 ↔ 2025») и «пополам» — граница по медиане дат, так что в периодах почти поровну материалов, а материалы одного дня не разделяются;
- таблица показателей: среднее и медиана в A и B, разница B − A, p (Манн–Уитни), r, вывод; разница окрашивается только при значимом различии;
- таблица проблем: доля материалов в A и B, разница в процентных пунктах, p с поправкой Холма;
- пересекающиеся периоды не тестируются (материал попал бы в обе группы), при группах меньше 2 материалов — только описательные значения;
- рисунок (столбцы A и B по K1–K5 и LPSI) и выгрузка в Excel с указанием периодов и фильтров страницы.

Карточка «Statistik ahamiyat» получила вкладку **«Годы»** — Краскел–Уоллис по годам как отдельным группам; тот же раздел есть в листе Excel «Значимость различий».

**Рейтинг** (карточка «Reyting»):
- **издания** — место по среднему LPSI или любому критерию K1–K5; равные значения (с округлением до 0,1, как на экране) делят место («=2»), следующее место пропускается; издания с числом материалов меньше 3 отмечены как условные; рисунок рейтинга;
- **материалы** — 10 лучших и 10 худших (если материалов не больше 20 — один полный список), со ссылкой на анализ.

Лист Excel **«Рейтинг»**: места изданий по LPSI и по каждому критерию, 10 лучших и 10 худших материалов по LPSI.

## Рисунки для диссертации

У каждого графика (Bosh panel, Analitika, сравнение кодировщиков) есть кнопка «Rasm» («Рисунок», «Figure»). Рисунок строится заново из тех же данных — не снимок экрана: белый фон, шрифт для печати, язык интерфейса, независимо от светлой или тёмной темы.

- **Настройки:** ширина 8 / 12 / 16 / 17 см, Times New Roman или Arial, кегль 9–14 пт, цветной или чёрно-белый вариант (в ч/б серии различаются оттенком, штрихом линии и формой маркера), заголовок внутри рисунка — по желанию (обычно подпись «Рисунок 2.1 – …» пишется в Word).
- **PNG** 150 / 300 / 600 dpi; в файл записывается разрешение, поэтому Word вставляет рисунок ровно выбранной ширины.
- **SVG** — вектор, для Word 2016 и новее.
- **Копировать** — рисунок в буфер обмена, вставка в Word через Ctrl+V.

Длинные подписи переносятся по словам и дефисам, при нехватке места шрифт подписей столбцов уменьшается. Генератор — `lib/rasm.ts` (без зависимостей, покрыт тестами).

## Отчёт по изданию (PDF)

Сводный документ по одному изданию для редакционного анализа, на языке интерфейса. Открывается на странице «Hisobot» (карточка «Отчёт по изданию»: издание и, по желанию, период) или кнопкой «PDF» в строке рейтинга на странице «Analitika» — тогда берётся период из фильтра страницы.

Содержание (3–4 страницы А4):
- **Общие показатели:** средний LPSI и уровень, место среди изданий, отличие от среднего по корпусу и по своему типу СМИ, сколько материалов размечено;
- **Оценки по критериям:** K1–K5 и LPSI — полоса издания с отметкой среднего по корпусу, разница, место, p (Манн–Уитни: издание против остальных изданий);
- **Сильные стороны и зоны внимания** — по прозрачному правилу: показатель отличается от среднего на ±5 баллов, доля проблемы — на ±10 п.п.; статистически значимые отмечены. Текст строится по правилу, без искусственного интеллекта;
- **Профиль проблем** (доля материалов, разница, число единиц, p по Фишеру с поправкой Холма) и прагматические средства;
- в какой части текста проблемы, семантико-прагматическое соответствие (доли «соответствует / частично / не соответствует» против корпуса), типы заголовков;
- динамика LPSI издания и корпуса (месяцы, кварталы или годы — по длине периода);
- **типичные примеры** самых частых проблем из корпуса примеров: сначала избранные ★ и подтверждённые экспертами, фрагмент выделен в предложении;
- материалы с самой высокой и самой низкой оценкой, описание методики расчёта.

Корпус для сравнения — все издания за тот же период. Если в издании меньше 5 материалов, отчёт предупреждает, что выводы предварительные.

## Корпус примеров

Страница «Misollar» («Примеры», «Examples») собирает все пометки с фрагментом, чтобы подкрепить цифры аналитики примерами из текстов.

- **Контекст.** Фрагмент показывается выделенным внутри своего предложения (заголовок — целиком). Границы предложения: `. ! ? …` и абзац; инициалы вроде «Sh. Mirziyoyev» границей не считаются. Фрагмент ищется в тексте без учёта регистра, лишних пробелов и вида апострофа (o‘ / o' / oʻ).
- **Подтверждение экспертов** «2/3»: из экспертов, разметивших материал, столько отметили ту же категорию в той же части текста фрагментом, который совпадает с фрагментом исследователя или пересекается с ним.
- **Фильтры:** поиск (по фрагменту, предложению, комментарию, заголовку), категория или группа категорий, часть текста, тип СМИ, издание, жанр, период, «только избранное», «подтверждено экспертом», «только завершённые анализы»; порядок — по категориям, по дате, по изданиям, по подтверждению. Фильтр хранится в адресе страницы. Над списком — число примеров по каждой категории.
- **Из аналитики:** ячейки «Muammo xaritasi» и «по частям текста» — ссылки на корпус с тем же разрезом и фильтрами (только завершённые анализы — та же основа, что у таблицы).
- **Избранное ★** хранится в базе и привязано к фрагменту, а не к номеру пометки: повторное сохранение анализа его не сбрасывает; если пометку удалить, отметка тоже удаляется.
- **Для Word:** нумерованный список «(1) «Предложение с **фрагментом**.» (Kun.uz, 12.03.2025)» — Times New Roman, интервал 1,5. Всё предложение или только фрагмент; выделение полужирным, курсивом или подчёркиванием; нумерация (1) / 1. / без номеров с любого первого номера (чтобы продолжить нумерацию главы); группировка по категориям, заголовок материала и комментарий — по желанию. Кавычки внутри цитаты заменяются на „ “.
- **Excel:** те же примеры с текущими фильтрами, фрагмент в предложении выделен полужирным, автофильтр по колонкам.

## Сбор материалов (ТЗ v2, этап 2)

Платформа не создаёт тексты сама: в базу попадает только то, что взято из реального источника, и каждый материал помнит, откуда он.

| Источник | Как добавить | Что сохраняется |
|---|---|---|
| **Ссылка** (цифровые издания) | «Mediabaza → По ссылке» | Заголовок, лид, текст, дата, издание и рубрика берутся со страницы; форма заполняется, исследователь проверяет и сохраняет. Сохраняются ссылка, время получения, хеш текста и копия исходной страницы (HTML, в сжатом виде) |
| **Файл** (печатные издания) | «Mediabaza → Из файла» | PDF или изображение страницы. Из текстового PDF текст берётся напрямую, сканированная страница распознаётся (OCR, узбекская латиница и кириллица, русский). Всё выполняется в браузере, файл на сервер не отправляется |
| **Импорт** | «Mediabaza → Импорт» | См. раздел ниже |
| **Вручную** | «+ Новый материал» | — |

- **Правила для сайтов.** Kun.uz, Qalampir.uz и Oyina.uz разбираются по своей разметке. Остальные сайты — общим способом: данные JSON-LD, мета-теги и алгоритм Readability. Если на сайте нет отдельного лида, нет года в дате и т. п., форма показывает предупреждение.
- **Повторы.** Материал с той же ссылкой (без учёта `www`, меток `utm_*`, `/` в конце) или с тем же текстом (по хешу SHA-256) повторно не добавляется: ни вручную, ни по ссылке, ни импортом.
- **Проверка OCR.** Распознанный текст сохраняется как «не проверен». Пока исследователь не отметит «Текст сверен с оригиналом», материал не попадает в анализ, экспертам и статистику.
- **Что считается в статистике.** Панель, аналитика, корпус примеров, отчёты Excel и PDF, согласованность экспертов учитывают только проверенные и не синтетические материалы. Сколько материалов осталось за рамками, видно на панели. Образцы (синтетические) помечены «Namuna (sun’iy)»; в демо-режиме (`start_web_demo.bat`, переменная `MEDIAPRAG_NAMOYISH=1`) они показываются, иначе демо было бы пустым.
- **Источник виден везде.** В карточке анализа — ссылка, время получения и копия исходной страницы (скачивается файлом). В Excel — колонки «Источник» и «Дата получения». В PDF-карточке — тоже.
- **Копия исходной страницы** хранится отдельно и в резервные копии не входит, чтобы они не разрастались. После восстановления копии исходных страниц сохраняются у тех же материалов.

## Подсказки AI (ТЗ v2, этап 3)

AI (Claude, модель `claude-opus-5-5`) читает материал и **только предлагает** разметку по критериям III главы. В разметку, LPSI, графики и отчёты попадает лишь то, что исследователь подтвердил. Если AI выключен, платформа работает вручную, как раньше.

1. В карточке анализа (администратор, основная разметка) — кнопка **«Получить подсказку AI»**. Сервер отправляет в Claude текст материала и определения критериев; ответ приходит строго по схеме (structured outputs).
2. Подсказки показываются **жёлтым** с пометкой «AI taklifi» прямо у полей формы: тип заголовка, соответствие «заголовок ↔ лид ↔ основной текст», композиция. Предложенные пометки (фрагмент + одна из категорий) показываются в блоках C и D. У каждой подсказки — короткое обоснование и уверенность (низкая / средняя / высокая).
3. Для каждой подсказки: **Подтвердить**, **Изменить** (значение переносится в форму, исследователь его правит; для пометки выбирается другая категория), **Отклонить**. Ничего не сохраняется само: решения записываются при нажатии «Сохранить».
4. **AI не придумывает текст:** если предложенного фрагмента нет в материале дословно, подсказка отбрасывается (сколько отброшено — видно на панели).

**Что хранится** (ТЗ, разделы 4.3–4.4 и 6):

| Где | Что |
|---|---|
| `ai_takliflar` | каждая подсказка: блок, значение, обоснование, уверенность, модель, версия промпта; итоговое решение исследователя (подтверждено / изменено / отклонено), итоговое значение, кто и когда решил |
| `ai_promptlar` | полный текст каждой версии промпта (версия — по хешу текста) |
| `ai_sorovlar` | каждый запрос: кто, когда, модель, токены, итог — для дневного лимита и оценки расходов |
| `belgilar` | статус пометки: вручную / AI подтверждено / AI изменено, кто подтвердил и когда |

**Согласие AI и исследователя.** На странице «Аналитика» — процент совпадений и каппа Коэна по типам заголовков, блокам соответствия, композиции и каждой категории пометок (шкала Лэндиса–Коха), с перечнем моделей и версий промпта. То же — отдельным листом в Excel.

**Методологическая справка** (ТЗ, раздел 7) — внизу Excel-отчёта и PDF-отчёта по изданию: число материалов, период, использовался ли AI и согласие AI с исследователем. В PDF-карточке материала указано, сколько пометок пришло из подсказок AI.

**Настройка** — «Методика → Помощник AI» (только администратор):
- включение и выключение подсказок;
- дневной лимит запросов (по умолчанию 100);
- **определения критериев**, которые получает AI. По умолчанию стоит черновик, его стоит заменить формулировками III главы диссертации. Каждое изменение текста — новая версия промпта.

**Ключ API** — переменная `ANTHROPIC_API_KEY` в Vercel (Settings → Environment Variables), только на сервере; в браузер и в отчёты он не попадает. Модель и глубину рассуждения можно сменить переменными `MEDIAPRAG_AI_MODEL` и `MEDIAPRAG_AI_EFFORT` (по умолчанию `claude-opus-5-5` и `high`). Если модель откажется отвечать, запрос автоматически повторяется на резервной модели (server-side fallback). Для длинных материалов ответ может занимать до нескольких минут: на Vercel нужен Fluid compute (включён по умолчанию у новых проектов).

Ориентировочная стоимость — несколько центов за материал (Claude Opus 5.5: $4 / $20 за миллион входных / выходных токенов); точные токены каждого запроса сохраняются в `ai_sorovlar`.

## Импорт материалов

«Mediabaza» → «Import (Excel / CSV)».

1. **Шаблон** `.xlsx` содержит выпадающие списки изданий, типа СМИ и жанров, а также лист с описанием колонок. Можно загружать и свой файл: колонки узнаются по названию на узбекском (латиница и кириллица), русском или английском (`Sarlavha` / `Сарлавҳа` / `Заголовок` / `Title`), порядок колонок не важен. Обязательны только «Nashr» и «Sarlavha».
2. **Предпросмотр.** Каждая строка проверяется, в базу ничего не пишется:
   - даты (`15.03.2025`, `2025-03-15`, даты Excel) и ссылки (к `www.` дописывается `https://`);
   - незнакомые издания — их можно создать, выбрав тип СМИ;
   - дубликаты (то же издание и тот же заголовок) в базе и внутри файла;
   - точные повторы — та же ссылка или тот же текст: такие строки попадают в список ошибок и не импортируются.

   CSV читается с разделителями `,` `;` и табуляцией, в кодировках UTF-8 и Windows-1251 (так сохраняет Excel).
3. **Импорт** выполняется одной транзакцией. Строки с ошибками и (по выбору) дубликаты пропускаются. Сервер заново проверяет исходные значения файла, а не данные, пришедшие из браузера.

Ограничения: до 5000 строк и до 15 МБ за раз; старый формат `.xls` нужно пересохранить как `.xlsx`.

## Экспертная оценка (v3)

**Кодирование несколькими экспертами.** В карточке анализа переключатель «Baholovchi» выбирает, кто размечает: исследователь (основной анализ) или эксперт. Эксперт кодирует материал независимо: чужие пометки ему не видны, а его разметка не попадает в основную статистику и используется только для оценки надёжности.

**Согласованность кодирования** — α Криппендорфа с учётом уровня шкалы:
- соответствия, композиция, аудитория — порядковая;
- типы заголовков — номинальная (каждый тип размечается как «есть / нет»);
- число пометок, K1–K5, LPSI — интервальная.

Интерпретация (Krippendorff, 2004): α ≥ 0,800 — надёжно; 0,667–0,800 — только для предварительных выводов; ниже — ненадёжно. Основной анализ исследователя можно включить в расчёт как ещё одного кодировщика или исключить.

**Обоснование весов.** Каждый эксперт распределяет 100 баллов между K1–K5. Платформа считает среднее, медиану, SD и коэффициент вариации (CV ≤ 33 % — мнения однородны), а также **коэффициент конкордации Кендалла W** с поправкой на связанные ранги и проверкой значимости по χ². Предлагаемые веса — среднее экспертов, округлённое до 0,5 с суммой 100. Кнопка «qo‘llash» создаёт новую версию методики с пометкой (n, W, p) и пересчитывает все анализы.

**Проверка расчётов:** `npm test` — 140 тестов (подсказки AI и каппа Коэна, сбор материалов и повторы, интеграция с PostgreSQL на PGlite, вход и права, статистика, тесты значимости, сравнение периодов и рейтинг, рисунки, корпус примеров, резервные копии, разбор файлов импорта). Реализация α воспроизводит эталонный пример Криппендорфа (2011): номинальная шкала 0,743, порядковая 0,815, интервальная 0,849. Сверены также W Кендалла и критические значения χ².

## Резервная копия

Работа с копиями — на странице «Hisobot», в карточке «Резервная копия данных» (только администратор).

- **Создать копию** — полный и согласованный снимок всех данных: материалы, разметка, эксперты, избранное ★, история методики. Учётные записи пользователей в копию не входят.
- **Где хранятся копии.** В самой базе, в сжатом виде, потому что у Vercel нет постоянного диска. Если база или сервис выйдут из строя, пропадут и копии, поэтому после важных этапов скачивайте копию (`.json.gz`) и храните её отдельно.
- **Автоматически:** каждую ночь по расписанию Vercel Cron (нужна переменная `CRON_SECRET`), а также при работе с платформой, если копии за сегодня ещё нет (хранятся последние 14). Перед каждым восстановлением — копия текущего состояния (последние 10). Созданные вручную и загруженные копии сами не удаляются.
- **Добавить из файла** — скачанная ранее копия (`.json.gz`) или старая база SQLite (`.db`). Файл проверяется: формат, целостность, наличие таблиц MediaPrag.
- **Восстановить.**
  - Перед заменой показывается сравнение «сейчас / в копии».
  - Замена идёт одной транзакцией; при любой ошибке база остаётся прежней.
  - Нумерация записей восстанавливается.
  - Учётные записи не трогаются, а учётные записи экспертов заново привязываются к экспертам по имени.
